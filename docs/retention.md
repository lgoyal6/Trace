# Deletion and redaction

`backend/app/corpus/retention.py` records deletion and redaction requests in an
append-only tombstone log. Deletion takes precedence over redaction regardless
of request order. Redaction replaces document-derived titles and abstracts with
`[redacted]`; curated condition, rarity and atlas labels remain countable.

## Storage inventory

| Surface | Behavior |
| --- | --- |
| `backend/data/corpus.json` | Local source of record and shipped fixture/export; rewritten with tombstones applied. |
| `NEULIT.CORE.PAPERS` | Snowflake source of record; bound purge statements are generated by `delete_record`. A caller must explicitly execute them with a live session. |
| Local vector store | When supplied to `delete_record`, deleted rows are removed and redacted text/embeddings are replaced. |
| `NEULIT.CORE.PAPERS_SEARCH` | Derived Cortex Search index with a declared one-hour target lag. Base-table purge does not prove immediate index erasure. Generated SQL requests a refresh. |
| Process caches | Corpus fixture cache, prompt cache and tombstone cache are invalidated by the deletion operation. |
| API exports | Query, streaming query and demo-contrast reads use retention filtering to suppress deleted records and blank redacted text. |

The checked measurement result files contain counts rather than paper text or
PMIDs. Any new export or cache must be checked separately before it is included
in this inventory.

## Read enforcement

`RetentionFilteredRetrieval` wraps a retrieval adapter. It excludes deleted
PMIDs from search and direct lookup and applies redaction to returned papers.
It withholds condition aggregates whenever any source is deleted because those
rows have no per-source provenance for subtracting deleted records. Redaction
alone preserves condition counts.

Default tombstone reads refresh using the log path, nanosecond modification time
and file size. `invalidate_caches()` forces a reload if the filesystem cannot
show a change. An explicitly supplied fixture log remains pinned. Callers must
apply enforcement when serving reads; this is a read-path guarantee while a
derived index catches up, not a claim of instant physical deletion.

`delete_record` returns a per-store receipt. Local purges, generated-but-unrun
Snowflake SQL, read filtering and backup retention are separate outcomes. A
receipt must not be treated as proof that generated SQL ran. The optional
`execute_snowflake_purge` path requires a live session and verifies deleted rows
in the base table; it does not prove derived-index or backup erasure.

## Backups and historical copies

Live-store deletion does not purge backups. Snowflake Time Travel follows the
actual account/table `DATA_RETENTION_TIME_IN_DAYS` setting. Permanent-table
Fail-safe is a fixed seven days after Time Travel expires and cannot be shortened
or purged by this code. Git history retains earlier corpus blobs indefinitely
unless history is separately rewritten.

`BACKUP_STORES` is a declared inventory, not a measurement of the live account.
Operators must reconcile it against actual retention settings with authorized
credentials before quoting a retention period to a data subject. Live Snowflake
retention and deletion verification remain unperformed without that access.
